# 格式约定

> 依据《蜉熵阁文件体系分类整理纲领》核心原则 4「中英文各司其职」，及 3.3 节中英文混用界定。
> 本仓库要托管在 GitHub 上，既是给人读的，也是给工具读的。两者要的东西不一样，所以分层处理。

## 一句话

**schema 用英文，文档用中文。**

- **schema** —— 会被程序解析的东西：frontmatter 的键名、枚举取值、CSV 列名、代码块里的符号。这些必须是英文标准格式，改一个字母就可能让解析脚本失效。
- **文档** —— 只给人读的东西：目录名、文件名、`title` 的值、正文、备注。这些用中文，因为读者是中文使用者，文件名还要能当摘要用。

## 分界表

| 类别 | 用什么 | 理由 |
| --- | --- | --- |
| 顶层 `README.md` `CHANGELOG.md` `FILE-TREE.txt` | 英文 | GitHub 载体惯例，工具与平台依赖这些名字 |
| 子目录名（`命题/` `元规则/` `分层/` `索引/` `历史/` `推导/` `评审/`） | 中文 | 一眼看懂装的是什么 |
| 命题文件名（`L1.1-现实不完全取决于特定主体的认识.md`） | 编号 + 中文标题 | 命名即摘要，扫目录就知道讲了什么 |
| 元规则、分层方案文件名 | 中文 | 说明性文档 |
| frontmatter 键（`id` `title` `level` `type` `status`） | 英文 | schema，脚本按这些键取值 |
| frontmatter 枚举（`postulate` `proposed`） | 英文 | schema，代码要 switch |
| `title` 的值 | 中文 | 内容 |
| CSV 列名（`id,title,level,type,status,path,notes`） | 英文 | schema |
| CSV 的 `path` 列值 | 中文路径 | 它是数据，指向真实文件 |
| 代码块里的符号（`W`、`Mᵢ(t)`、`P_t`） | 原样 | 符号系统不翻译 |
| 正文、章节标题、备注 | 中文 | 内容 |

## 中文名对照

中文名只出现在正文、说明和本表里，**不写进 frontmatter 和 CSV 列名**。

## 新增术语怎么办

1. 先定英文 `code`，小写、连字符分隔。
2. 再给中文名，登记到本文件的对应表。
3. 中文名只进正文和本表；`frontmatter`、CSV 列名一律用 `code`。

**不要反过来做。** 一旦 `type` 变成中文，第一条解析脚本就坏。
