# S 层｜运行规格映射

_本层对应既有资产「心智模型完整版」（云盘 `知识库/心智模型/完整版/`，17 文件约 190KB）。整合后改称 S 层，层级符号由「L0-L3」改为 `S0-S3`，避免与 L 层的论证层级撞车。_

## 一、本层的职责边界

本层描述的是**系统具体怎么跑、什么算跑对了**：类型约束、操作语义、状态转换、不变式、验证规则。

本层**不**对世界如何运作作任何断言。规格描述的是执行规则，不是关于 `W` 的主张——参见 `L2.2`（规格层与认识层的接口）。

## 三、36 条既有不变式的性质判定

对 `INVARIANTS.md` 全部 36 条不变式做过一次性质审查，结论：

| 类别 | 数量 | 性质 | 是否含哲学主张 |
| --- | --- | --- | --- |
| 类型不变式（SCHEMA 衍生） | 8 | 数据格式约束 | 无 |
| 操作不变式（SEMANTICS 衍生） | 12 | 流程完整性约束 | 无 |
| 验证不变式（VALIDATION 衍生） | 6 | 检查规则 | 隐含"一致性=正确"（见下节 C3） |
| 状态不变式（STATES 衍生） | 10 | 状态转换合法性 | 无 |

**重要结论**：36 条全部是工程约束（时间戳范围、字符串长度、文件命名、心跳间隔、安静时段），**没有一条涉及真理、真实、绝对、永久、必然**。因此 S 层与 L 层之间**不存在实质理论冲突**——缺的只是接口，不是仲裁。

## 四、新增元不变式（2 条）

原有 36 条全部回答"该怎么跑"，没有一条回答"规则本身错了怎么办"。以下两条补这个缺口。

### INV-META-001 · 规格条款的可修订性

```yaml
INV-META-001:
  名称: 规格修订须走上游政策
  描述: 任何规格条款的修订，必须走 L 层的修订政策六步流程，不得在规格层就地改写
  形式化: ∀r ∈ Revision: r ∈ Specs → r.path = revision-policy.six_steps
  六步: [保存旧版, 描述问题类型, 给新版与理由, 检查下游受影响的条款, 更新索引, 记决策日志]
  依据: L2.2 规格层与认识层的接口；L1.3 认识可能出错且可以修订
  违反后果: 规格成为事实上的不可质疑底座，与 L1.3 直接冲突
```

**为什么必须有这一条**：190KB 的规格若无自我修订条款，它就变成了事实上的公理系统。而整个 L 层的努力恰恰在反对这件事——`L0.1` 明确说体系从"正在发生的认识活动"出发，不预先假定一个不可动摇的底座。规格层如果拒绝被修订，等于在底层偷偷安回一个底座。

### INV-META-002 · 一致性 PASS 不等于正确

```yaml
INV-META-002:
  名称: PASS 的正确性边界
  描述: L3 三方一致性验证 PASS，只表示系统内身份-行为-记忆无矛盾，不表示身份模型正确
  形式化: PASS(L3) → Consistent(Identity, Behavior, Memory) ∧ ¬Proven(Correct(Identity))
  依据: L1.4 主体间共识不等于真实（协调性 ≠ 可检验性 ≠ 真实性）；L1.7 无可修正可能只是局部最优
  禁止推论: 不得以 PASS 作为"身份模型正确"的证据；不得因 PASS 而降低对身份定义本身的审查
```

**为什么必须有这一条**：`VALIDATION.md` 的 L3 层要验证"身份-行为-记忆三方一致性"。但如果身份定义本身是错的，高一致性反而意味着**错误被固化得更牢**。这是 `L1.4`"共识不等于真实"在单个主体内部的镜像——三方一致性是系统内协调性，不是关于这个主体的真实性。

## 五、与 L 层的术语对照

`VALIDATION.md` 在开头需建立以下术语对照，避免把工程结果误读为认识论结论：

| L 层术语 | S 层对应物 | 关键区别 |
| --- | --- | --- |
| 协调性 | L3 一致性 PASS | 系统内无矛盾，不涉及外部真实性 |
| 公共可检验性 | L2 验证规则可执行 | 规则可跑，不代表规则测对了对象 |
| 真实性 | — | **S 层无法直接验证真实性**，只能给出间接指标 |
| 可错性 | INV-META-001 | 规格条款可被修订 |
| 局部最优 | INV-META-002 | PASS 的长期稳定可能是盲点而非正确 |
